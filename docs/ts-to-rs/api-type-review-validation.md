## Typed boundaries

- Execution metadata is decoded once from the actual TS registry into `EndpointMeta` and `RateLimit`. Malformed execution fields fail bootstrap before readiness; documentation remains owned by the registry. Missing/null limiter members retain their existing meaning. Binary64 values preserve fractional, negative and zero behavior rather than silently imposing integer/positive constraints.
- `PolicySnapshot` no longer implements `Deref`. JSON projection is explicit; numeric authorization/limiting decisions use the completed numeric aggregation, retaining NaN, infinities and signed zero before JSON projection. A compile-fail doctest prevents accidental JSON indexing through the snapshot.
- The policy-name/aggregation descriptor is generated from the authoritative TS `RoleService`. The AST generator validates policy type/default/returned keys, operation bodies and aggregation prelude; unknown source shapes fail closed. The Bun native build checks generated bytes before Cargo or executable publication. Existing backend CI builds traverse that path; no CI job or test behavior is replaced.
- The JavaScript value API separates borrowed UTF-16 (`as_utf16`) from allocating exact UTF-8 conversion (`to_utf8`). Unpaired surrogates remain representable and conversion never inserts replacement characters.
- Rate limiting accepts typed configuration and returns `LimitInfo` with binary64 fields; JSON is an explicit response projection. Default endpoint keys, empty keys and shared keys remain distinct.
- The host Redis stream first validates a borrowed raw JSON envelope. Irrelevant channels do not decode arbitrary business payloads into a UTF-8 tree. Last duplicate channel/message wins, including escaped key spellings. Lone surrogates and deep unrelated messages no longer close authentication admission. Malformed JSON or internal invalidation remains fail closed; a replacement stream that closes while refreshing does not reopen admission.
- API routing/authentication/authorization/validation/dispatch/cache/callback phases are separate methods. Known public failures use typed gate definitions and response payloads, preserving omitted members, nulls, challenges, identifiers and UTF-16 serialization. Runtime and Redis failures retain sanitized stages; diagnostic logs contain neither SQL/parameters nor credentials/capabilities.
