## Existing five-operation RPC contract

Use an independent Cargo workspace at `packages/backend-rust`, with std-only `core`, a separate `storage-postgres` adapter, and `bridge` depending on Tokio 1, Axum 0.8, Serde 1, serde_json 1, thiserror 2, tracing 0.1 and tracing-subscriber 0.3. Pin Rust 1.99.0 and include Cargo.lock in the authorized implementation commit. Business types/functions must not depend on the temporary RPC adapter.

The bridge listens on `127.0.0.1:0`. One HTTP POST `/rpc` performs one operation. All request and success response envelopes have `v: 1` and `op: 'ping' | 'test' | 'endpoint' | 'endpoints' | 'get-online-users-count'`. Authenticate with `Authorization: Bearer <32-random-byte-token-as-hex>` received through stdin, never CLI arguments or logs. No retry, automatic restart, or TS fallback.

| Operation | Request fields | Success response fields |
| --- | --- | --- |
| ping | none | `pong: number` (safe signed integer Unix milliseconds, read in Rust) |
| test | `paramsJson: string` | `resultJson: string` |
| endpoint | `endpointUtf16: number[]` | `result: null | {params: {nameUtf16: number[], type: string}[]}` |
| endpoints | none | `endpointsUtf16: number[][]` |
| get-online-users-count | none | `count: number` (nonnegative integer JavaScript Number, up to the rounded PostgreSQL int8 maximum) |

TS validates every response from unknown, including version and operation. `test` serializes the complete AJV-validated params object with JSON.stringify. Rust treats the inner JSON text as opaque and echoes it. TS requires the returned text to equal the sent text and restores a validated object before returning it to the existing HTTP sender. Preserve additional properties, defaults/null distinctions, property order, number serialization and lone UTF-16 surrogates. Never expose the inner JSON as a public JSON string. Do not introduce unchecked generic result casts.

Bootstrap is one newline-terminated JSON frame `{v:1,token,endpoints,postgres}`. `postgres` is optional/null for catalog-only callers, otherwise `{targets:[...]}` with resolved connection settings; it never appears in argv, readiness, or logs. Endpoints are an ordered array of `{nameUtf16,properties:[{nameUtf16,type}]}`, where type is null for an absent type, otherwise the current schema's ASCII type. Extract it from the actual endpoint registry using Object.entries on top-level properties only. No allOf/anyOf expansion. Lookup is first exact UTF-16 match. Explicit types capitalize only their first ASCII character; absent type stays lowercase `string`. Unknown endpoint returns null and public HTTP remains 204 with no body. The list operation uses the same ordered Catalog and encodes each name as its exact UTF-16 code units, including empty names, duplicates, NUL, and lone surrogates. TS validates the version, operation, outer list, and every inner integer in 0..65535 before reconstructing strings; empty catalog returns an empty array. Definitions are immutable for one child lifetime. The complete bootstrap must be accepted before readiness.

Ready stdout frame: `{v:1,port}` followed by newline, maximum 4 KiB. Stdout is control-only; stderr is logs. Bootstrap and RPC request/response maximum: 16 MiB. Public 1 MiB body limit stays unchanged. Read sizes incrementally; do not allocate unbounded responses. All RPC/protocol/transport failures map to ApiError `RUST_BACKEND_UNAVAILABLE`, kind `server`, HTTP 503, with a fixed error ID and no internal details.

## Online-user operation and PostgreSQL

`core` remains std-only. Sample `SystemTime` once on operation entry, take Unix milliseconds, subtract 600,000, and query `SELECT COUNT(*) FROM "user" WHERE "lastActiveDate" > $1`. The column is nullable `timestamptz`. Bind an absolute timestamp at JS millisecond precision, preserve sub-millisecond DB values, exclude NULL and the exact cutoff, include later/future values. Empty table returns zero. No visibility, suspension, or account-type filtering is added.

COUNT is a nonnegative PostgreSQL int8. Existing `pg.types.setTypeParser(20, Number)` plus TypeORM `parseInt` rounds above 2^53. Rust intentionally keeps that Number conversion through i64::MAX, including its rounded 2^63 value. TS verifies a finite integer in that range, without imposing a new safe-integer restriction. The existing operation RPC still uses the TS serializer; public API execution now uses the Rust JS-compatible value formatter.

`storage-postgres::OnlineUsers` owns the complete operation and can be called without RPC by a future Rust HTTP application. It uses tokio-postgres and OpenSSL separately from core. Create connections lazily under the configured native source-pool budget, and select a slave per operation when replication is enabled (master only when there are no slaves). The original one-connection slot remains the compatibility policy for v1 bootstrap and explicitly held exotic pool settings. Do not fall back to the master when a selected slave fails. Set a read-only session before the count. Bound the complete operation, including checkout and connect/query, to four seconds; honor shorter configured client deadlines at their existing boundaries and existing server timeouts. On cancellation/transport failure discard the connection and join its aborted driver; a completed server SQL error may return its healthy lease. Closing TCP alone does not interrupt PostgreSQL lock waits, so an unfinished query also sends a bounded (500 ms) protocol CancelRequest using the same TLS policy. Track cleanup and retain its capacity reservation until disposal completes; this is cancellation, never an SQL retry. If the network cannot deliver cancellation, server-side termination is not guaranteed. Shutdown interrupts connection establishment as well as queries. A later independent request may establish a fresh connection; the failed request is never replayed. Shutdown rejects new operations and bounds connection disposal to one second. The existing catalog and clock/echo operations acquire no database connection.

Normalize settings using the installed `pg.Client` constructor and startup/password resolution without opening a TS connection. Preserve base/extra/connectionString/PG environment precedence, pgpass matching and permissions, read targets, startup options, application name, timeouts, keepalive and channel binding. Transfer credentials and PEM data only through stdin. TLS enabled means required TLS, with no plaintext fallback; retain the resolved CA trust, verification, hostname/SNI, client certificate/key/passphrase, protocol bounds, cipher settings, and direct negotiation. Explicitly configured no-verify retains the existing setting; never introduce it as a workaround.

The small adapter cannot serialize arbitrary JS callbacks/streams/custom TLS contexts or arbitrary `pg` extensions. Unsupported effective connection/TLS settings fail closed for this operation (503), without preventing the original four operations from starting; never silently discard such a setting. TS pools retain their own sizing/lifetime policy, while native operations share the effective per-source budget described in the pooling unit. This is not a combined TS/Rust connection cap. Exotic pool settings and checkout public-error projection remain explicit compatibility holds. The count-only adapter itself adds neither database roles nor schema nor Redis connections; the new API application separately owns its approved Redis connections. The detailed supported/unsupported settings and runtime evidence are recorded with this unit.

## Process and build lifecycle

One child per TS process that launches HTTP. RustBackendModule provides one shared RustBackendService; constructor/module initialization does not spawn. ServerService.launch awaits readiness before listening. Queue-only and metadata generation do not start Rust. Use operation-specific methods plus start/stop/isReady. Concurrent start/stop and double disposal are safe; a stopped instance does not restart.

Startup timeout 10 s; the existing five-operation RPC timeout is 5 s. The API application transport has no generic business-handler timeout. Startup errors clean up and reach an explicit fatal nonzero boot path, including worker startup reporting. Runtime child exit makes every public API route and healthz 503; non-API routes stay in TS. A single call timeout fails that call, without declaring a live child dead. Recovery requires backend restart. Public HTTP and WebSocket shutdown is bounded to 5 s total, followed in finally by child stop; graceful child stop has 2 s, then kill and wait at most 1 s. Monitor stdin EOF so a killed parent cannot orphan the child. Ensure blocking stdin readers cannot prevent process exit. Connect normal signals, cluster workers, E2E reset and dev restarts.

Bun invokes Cargo `--locked --release`, target output `built/target`, distributed executable `built/bin/misskey-backend-rust` (platform suffix where applicable). Publish atomically on success; failed compilation must stop subsequent startup. Rust package script is build:native, not build, to avoid duplicate root workspace builds. Integrate backend build/unit/e2e/tsc/dev paths and direct benchmark builder. Watch Rust sources/manifests/lock, serialize build/restart and collect old processes. Find binaries relative to code root, not Config.rootDir/storage or cwd.

Docker builds for the target platform and copies the executable after runner source copy; ignore host Rust built artifacts. CI path filters cover Rust/integration files, with fmt/clippy/test on Rust changes. Include Cargo sources/locks and exclude compiled artifacts in source tarballs. Extend clean commands.

Federation: independent one-shot builder reusing the existing Rust-capable federation test Dockerfile; dedicated named volume over backend-rust/built, RW builder and RO apps. Both concrete app services depend on builder success. Do not add dependencies to the shared app template that setup extends. Preserve host artifacts. Tester itself does not need the new binary.
